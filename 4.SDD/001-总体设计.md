# 001 总体设计：回调至亮之焰（RevertBrightestFlame）

- 版本：1.1.2
- 最后更新：2026-11-13
- 依据：`9.SRC/RevertBrightestFlame/` 现役源码、`1.ADR/` 三篇决策记录、
  `3.DOCS/001-R-升级收益被吞审阅报告.md`、`3.DOCS/002-T-三版本取证与实施笔记.md`、mod 清单
- 游戏环境：Slay the Spire 2 v0.111.0 / v0.113.0（0.113 兼容修复见 §13）

## 1. 设计目标

把 0.111.0 里被削弱的古代卡牌「至亮之焰」（`MegaCrit.Sts2.Core.Models.Cards.BrightestFlame`）
恢复为 0.107 / 0.110 的数值与文本：

| 属性 | 0.111.0 原版 | 本 mod |
|---|---|---|
| 最大生命损失（每次打出） | 2 | **1** |
| 费用 | 0 | 0（写死） |
| 未升级打出 | 获得 2 能量、抽 2 张牌、损失最大生命 | 同左 |
| 升级后打出 | 能量/抽牌各 +1，损失量不变 | 同左（3 能量 / 3 抽 / 损失 1） |
| 卡名 / 描述 | 官方文案 | 本 mod 本地化键，16 语言，取自 0.111.0 pck 解包原文 |

非目标：

- 不新增卡牌、不禁用原卡，直接修改原卡模型，使存档中的历史卡牌一并生效。
- 不写死卡面美术（`Portrait` / 图集），跟随游戏 pck 素材——ADR-002 明确列为「仍不可写死的部分」。
- 不改引擎通用框架（`CardModel.OnPlayWrapper` 的附魔/苦难/`AfterCardPlayed` 钩子、卡牌去向规则、升级状态机）。

## 2. 运行形态与加载链路

产物为 `dll + pck + json 清单` 三件套，安装到游戏 `mods/RevertBrightestFlame/`：

```
游戏启动
  └─ ModManager 读取 RevertBrightestFlame.json
      ├─ min_game_version=0.111.0 → 低于此版本：MOD_ERROR.GAME_VERSION_UNSUPPORTED，拒绝加载
      └─ 加载 dll → [ModInitializer("ModLoaded")] → ModEntry.ModLoaded()
           ├─ BrightestFlameShapeGuard.ValidateStatic()   ← 类型/成员存在性
           │    └─ 失败：记警告、不挂补丁，游戏保持原版行为
           ├─ new Harmony("RevertBrightestFlame")
           └─ PatchAll(Assembly.GetExecutingAssembly())    ← 13 个补丁类一次性挂载
```

- 清单字段：`id=RevertBrightestFlame`、`version=1.1.1`、`min_game_version=0.111.0`、
  `has_dll=true`、`has_pck=true`、`affects_gameplay=true`、`dependencies=[]`。
- `pck` 提供 `res://RevertBrightestFlame/` 下的 `mod_image.png`（420×420 占位图）与 16 个语言的
  `cards.json`；`export_presets.cfg` 的 `export_files` 显式列出这 17 个文件（225,072 字节）。
- `dll` 仅依赖游戏自带的 `sts2.dll` 与 `0Harmony.dll`（csproj 中 `Private=false`，不随包分发）。

## 3. 模块划分

| 模块 | 文件 | 职责 |
|---|---|---|
| 入口 | `ModEntry.cs` | `[ModInitializer("ModLoaded")]`；先跑静态守卫，再 `PatchAll`；异常只记日志不抛出 |
| 开关 | `ModConfig.cs` | `IsReplaceEnabled => BrightestFlameShapeGuard.IsSupported()`，全部补丁的统一闸门 |
| 数值补丁 | `Patches/BrightestFlameCanonicalVarsPatch.cs` | `BrightestFlame.CanonicalVars` getter Postfix → 固定 `MaxHpVar(1m)` / `EnergyVar(2)` / `CardsVar(2)` |
| 行为补丁 | `Patches/BrightestFlameOnPlayPatch.cs` | `OnPlay` Prefix 整体替换：能量与抽牌读实例 `DynamicVars`，最大生命损失固定 `1m` |
| 升级补丁 | `Patches/BrightestFlameOnUpgradePatch.cs` | `OnUpgrade` Prefix 整体替换：`DynamicVars.Energy/Cards.UpgradeValueBy(1m)` |
| 元数据补丁 | `Patches/BrightestFlameMetaPatches.cs` | 10 个补丁类：费用、`CardEnergyCost.Canonical` 兜底、类型、目标、稀有度、关键词、金色高亮、悬停提示、卡名、描述 |
| 守卫 | `Patches/BrightestFlameShapeGuard.cs` | `ValidateStatic()` 静态成员检查；`IsSupported()` 运行时 `ModelDb.Card<BrightestFlame>()` 确认卡牌存在 |
| 本地化 | `RevertBrightestFlame/localization/<lang>/cards.json` | 16 语言卡名与描述，键前缀 `RE_` |

补丁类合计 13 个（`Patches/` 下 4 个文件），守卫 1 个。

## 4. 补丁策略

| 目标成员 | 方式 | 写入值 |
|---|---|---|
| `BrightestFlame.CanonicalVars`（getter） | Postfix 替换返回值 | `MaxHpVar(1m)` / `EnergyVar(2)` / `CardsVar(2)` |
| `BrightestFlame.OnPlay` | Prefix 返回 `false`，自行返回 `Task` | `GainEnergy(DynamicVars.Energy.IntValue)` + `Draw(DynamicVars.Cards.BaseValue)` + `LoseMaxHp(1m, isFromCard:true)` |
| `BrightestFlame.OnUpgrade` | Prefix 返回 `false` | `Energy.UpgradeValueBy(1m)`、`Cards.UpgradeValueBy(1m)` |
| `CardModel.CanonicalEnergyCost`（getter） | Postfix | `0` |
| `CardEnergyCost.Canonical`（getter） | Postfix（反射读私有字段 `_card`） | `0` |
| `CardModel.Type` / `TargetType` / `Rarity` | Postfix | `Skill` / `Self` / `Ancient` |
| `CardModel.CanonicalKeywords` | Postfix | `Array.Empty<CardKeyword>()` |
| `CardModel.ShouldGlowGoldInternal` | Postfix | `false` |
| `BrightestFlame.ExtraHoverTips` | Postfix | 仅 `HoverTipFactory.ForEnergy(instance)` |
| `CardModel.TitleLocString` / `Description` | Postfix | `LocString("cards", "RE_BRIGHTEST_FLAME.title"/".description")` |

所有补丁体都是自包含字面量或读实例变量，不调用原版实现（`OnPlay`/`OnUpgrade` 直接 `return false`），
因此游戏更新改动这张卡的数值或文案不会影响结果；但**类型与成员签名**属于编译期依赖，
由守卫降级而非免疫（见 §6）。

## 5. 数据流

```
CanonicalVars（本 mod 写死 2/2/1）
   └─ CardModel.DynamicVars getter 实例级懒加载：_dynamicVars ??= new DynamicVarSet(CanonicalVars)
        ├─ 卡面描述：CardModel.GetDescriptionForPile → DynamicVars.AddTo(locString)
        │     └─ 本 mod 的 Description 补丁切到 RE_BRIGHTEST_FLAME.description，
        │        SmartFormat 用 {Energy}/{Cards}/{MaxHp} 占位符渲染 → 2/2/1（升级后 3/3/1）
        └─ 打出：本 mod 的 OnPlay 读 DynamicVars.Energy.IntValue / Cards.BaseValue，MaxHp 写死 1m

OnUpgrade（本 mod 写死 +1/+1）
   └─ DynamicVar.UpgradeValueBy(1m) → BaseValue 2 → 3（存档内升级状态存于 DynamicVars 克隆）
```

关键约束（ADR-003 的教训）：**执行层读变量、数值层写死**。若 `OnPlay` 用字面量，升级只改
`DynamicVars` 而字面量不变，升级收益会被吞掉——这正是 v1.1 的缺陷，v1.1.1 已修复。

## 6. 异常处理与降级

| 场景 | 行为 |
|---|---|
| 游戏版本 < 0.111.0 | 加载器依 `min_game_version` 拒绝加载，mod 显示为版本不支持 |
| 游戏删卡或补丁目标成员缺失 | `ValidateStatic()` 返回 `false` → 不挂任何补丁，仅 `Log.Warn`，游戏保持原版行为 |
| `ModelDb` 尚未就绪 | `IsSupported()` 捕获异常后**暂时放行**（`return true`），下次访问再评估 |
| `ModelDb` 中不存在至亮之焰 | `IsSupported()` 返回 `false`，全部补丁不生效 |
| 补丁挂载抛异常 | `ModEntry` 的 `try/catch` 记 `Log.Error`，不影响游戏启动 |

`ModConfig.IsReplaceEnabled` 是唯一闸门：所有 13 个补丁的补丁体都先判断它，未通过则
`OnPlay`/`OnUpgrade` 返回 `true` 放行原版逻辑，Postfix 不改写返回值。

## 7. 兼容与本地化

- 依赖面：仅 Harmony（游戏自带）+ 游戏程序集；无 RitsuLib、无第三方基础 mod。
- 本地化：`RE_BRIGHTEST_FLAME.title` / `.description` 共 16 个语言目录
  （deu/eng/esp/fra/ind/ita/jpn/kor/pol/ptb/rus/spa/tha/tur/zhs/zht），
  文本取自 0.111.0 pck 的 `localization/<lang>/cards.json` 原文（`languages/raw/` 与
  `languages/原文汇总.md` 留档），`RE_` 前缀避免与其它 mod 键冲突。
- 描述占位符保留 `{Energy:energyIcons()}` / `{Cards:diff()}` / `{MaxHp:diff()}` 等原文写法，
  由写死的 `DynamicVars` 渲染数值。
- 存档：直接改原卡模型，开启 mod 时历史记录中的至亮之焰按回调后数值显示，关闭后恢复官方值。

## 8. 构建方案

- 工程：`Godot.NET.Sdk/4.5.1`、`net9.0`、`AssemblyName=RevertBrightestFlame`、`Nullable=enable`、`NoWarn=MSB3270`。
- 引用：`$(Sts2Path)/data_sts2_windows_x86_64/sts2.dll` 与 `0Harmony.dll`（`Private=false`）。
- 构建脚本 `build.ps1`（PowerShell，`$ErrorActionPreference='Stop'`）：
  1. `dotnet build -c Debug` → `.godot/mono/temp/bin/Debug/RevertBrightestFlame.{dll,pdb}`
  2. Godot `--headless --import` 生成导入元数据
  3. Godot `--headless --export-pack "Windows Desktop"` 输出 `mods/RevertBrightestFlame/RevertBrightestFlame.pck`
  4. 拷贝 dll / pdb / json 到游戏 `mods/RevertBrightestFlame/`
- 本机路径（游戏目录、Godot 4.5.1 mono）硬编码在 `*.csproj` 与 `build.ps1` 顶部。

## 10. 已知问题与待实施

1. **`ShapeGuard` 检查项不全**（`Patches/BrightestFlameShapeGuard.cs`）：注释称检查「全部补丁目标成员」，
   但漏检 `BrightestFlame.CanonicalVars` getter 与 `CardEnergyCost.Canonical` getter。
   当前版本无影响；若未来游戏删改这两个成员，`Harmony.PatchAll` 可能中途抛错，出现
   「部分补丁已应用」的隐患。建议补两条 `AccessTools.PropertyGetter(...) != null`。
2. **发布仓库源码版本滞后**：本次整理前，远端仓库源码仍是 v1.1（`OnPlay` 字面量、清单 `version=1.1`）；
   本次整理随仓库提交同步到 v1.1.1。
3. **历史版本快照保持只读**：`TMP/04-历史版本源码/RevertBrightestFlame（1.0/1.1版本存档）/` 为未修复副本，不得据其构建。
