# ADR-001：至亮之焰数值回调的实现方式

- 日期：2026-08-15
- 状态：已实施，待实机验证
- 关联计划：`2.PLANS/001-G-回调至亮之焰施工计划.md`

## 背景

v0.111.0 将古代卡牌「至亮之焰」（Brightest Flame）的每次使用损失最大生命值从 1 改为 2。
需求：改回损失 1（仅改数字），且仅在 0.111.0 及以上版本生效。

## 决策

1. **补丁面最小化**：仅 Harmony Postfix `BrightestFlame.CanonicalVars` getter，返回
   `[MaxHpVar(1m), EnergyVar(2), CardsVar(2)]`。效果（OnPlay 读取 DynamicVars.MaxHp）与
   卡面文字（{MaxHp} 占位符）同步生效；不碰 OnPlay/Description/本地化，不需要换图。
2. **版本门槛用加载器原生机制**：manifest `min_game_version = "0.111.0"`，低于该版本
   游戏拒绝加载（`MOD_ERROR.GAME_VERSION_UNSUPPORTED`）。不加运行时版本/形状守卫——
   遵循 Scavenge/Recycle mod 的先例（仅 min_game_version + ModLoaded try/catch 兜底）。
3. **无本地化与素材**：不新增语言目录；pck 仅含空白占位图标 `mod_image.png`（420×420）。
4. **工程独立成仓**：置于 `C:\Users\13167\Desktop\Deepseek\STS2Mod-至亮之焰`，不与
   sts2-phantom-killer-mod / STS2Mod 两个既有工程混放。

## 备选方案与放弃原因

- 补丁 `OnPlay` 写死 1m：文字仍显示 2，效果与文字不一致，放弃。
- 补丁 `DynamicVar` 值 + Description 本地化覆盖：面更大、需 16 语言，收益为零，放弃。
- 运行时版本守卫（`ReleaseInfoManager.Instance.SemVer`）：加载器门槛已足够，且用户按
  Recycle 先例选择从简，放弃。

## 影响

- 升级行为不变（能量/抽牌 +1，损失量恒 1）。
- 107/110 上 mod 不加载（卡牌原本就是损失 1，无影响）。
- 未来版本若再改卡牌形态，需回归 `BrightestFlame.cs` diff（见 docs 笔记维护清单）。
