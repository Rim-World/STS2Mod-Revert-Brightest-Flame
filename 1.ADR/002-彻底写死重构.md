# ADR-002：至亮之焰「彻底写死」重构（元数据 + 描述 + 守卫）

- 日期：2026-08-16
- 状态：已实施并重新构建安装，待实机验证
- 关联计划：`2.PLANS/001-G-回调至亮之焰施工计划.md`；替代 ADR-001 的单一 CanonicalVars 补丁方案

## 背景

用户要求：彻底写死至亮之焰的整卡效果（升级前 + 升级后），且不受游戏更新给这张卡
添加属性或删除效果的影响。① 包含元数据写死；② 描述文字也写死（全部 16 语言）；
③ mod 加检测：确认游戏里有至亮之焰这张牌才启用。

## 决策

1. **全入口接管**（`Patches/` 下 10 个补丁 + 1 个守卫），补丁体全部自包含、不读原版实现：
   - `CanonicalVars` → 固定 `[MaxHpVar(1m), EnergyVar(2), CardsVar(2)]`
   - `OnPlay` → Prefix 整体替换：`GainEnergy(2m)` + `Draw(2m)` + `LoseMaxHp(1m)`
   - `OnUpgrade` → Prefix 整体替换：能量 +1、抽牌 +1（DynamicVar.UpgradeValueBy 引擎通用机制）
   - 元数据：`CanonicalEnergyCost=0`（含 `CardEnergyCost.Canonical` 兜底）、`Type=Skill`、
     `TargetType=Self`、`Rarity=Ancient`、`CanonicalKeywords=空`、`ShouldGlowGoldInternal=false`、
     `ExtraHoverTips=仅能量提示`
   - 文本：`TitleLocString` / `Description` → 本 mod 本地化键 `RE_BRIGHTEST_FLAME.title/.description`
2. **16 语言本地化写死**：`localization/<lang>/cards.json`，文案取自 v0.111.0 pck 解包原文
   （含 SmartFormat 占位符 `{Energy:energyIcons()}`/`{Cards:diff()}`/`{MaxHp:diff()}`，
   数值由写死 DynamicVars 渲染为 2/2/1），键加 `RE_` 前缀防冲突；
   解包原文另存 `languages/` 供审阅（`TOOLS/scripts/extract-brightest-localization.py` 可复用）。
3. **启用守卫**：`BrightestFlameShapeGuard` 两道检查——
   - `ValidateStatic()`（ModLoaded 时）：BrightestFlame 类型与全部补丁目标成员存在性，
     任一缺失 → 不应用任何补丁（游戏保持原版行为，仅日志警告，不崩溃）；
   - `IsSupported()`（运行时）：`ModelDb.Card<BrightestFlame>()` 确认游戏里确实有这张卡，
     ModelDb 未就绪时延迟评估；所有补丁经 `ModConfig.IsReplaceEnabled` 统一接入。
4. 版本门槛不变：manifest `min_game_version=0.111.0`（加载器原生拒绝低版本）。

## 边界说明（仍不可写死的部分）

- 卡面美术（Portrait/图集）未写死：跟随游戏 pck 素材；如需写死需把 1000×760/250×190 卡图
  打包进 mod 并补丁 `Portrait/PortraitPath/PortraitPngPath`。
- 引擎通用框架（OnPlayWrapper 的附魔/苦难/AfterCardPlayed 钩子、卡牌去向规则、升级状态机）
  是所有卡共享机制，不属于本卡属性。
- 类型/依赖 API 被游戏删除属编译期依赖：由守卫降级（禁用补丁）而非免疫，需 mod 更新。

## 影响

- 补丁面从 1 个增至 10 个，均沿用 STS2Revertantony / 本系列 mod 成熟写法。
- pck 从仅图标（3KB）变为 图标 + 16 语言文件（225KB）。
- 升级预览/图鉴/存档往返依赖 DynamicVar 机制，写死数值下渲染一致。
