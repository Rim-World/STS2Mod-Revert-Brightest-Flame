## 一、结论摘要

1. **主因确认**：v1.1（ADR-002「彻底写死」）的
   `Patches/BrightestFlameOnPlayPatch.cs` 把打出效果写成**固定字面量**
   2 能量 / 2 抽牌，完全不读取卡实例的 `DynamicVars`。升级只把
   `DynamicVars.Energy/Cards` 从 2 提到 3，字面量不会跟着变，
   于是**升级过的至亮之焰打出后仍只有 2 能量、2 抽牌**（损失 1 最大生命正常）。
2. **修复已实施并部署**（v1.1.1）：OnPlay 改为读取
   `DynamicVars.Energy.IntValue` / `DynamicVars.Cards.BaseValue`
   （与原版表达式逐字一致），最大生命损失仍固定 `1m`。
   基础 2/2/1 的"写死"职责保留在 `CanonicalVars` 补丁；升级 +1/+1 保留在
   `OnUpgrade` 补丁（`DynamicVar.UpgradeValueBy`）。升级后应为
   **3 能量 / 3 抽牌 / 损失 1 最大生命**。
3. 构建通过（0 错误 0 警告），产物已复制到游戏 mods 目录，dll 哈希与本地
   编译产物一致；**实机打出验证仍待用户执行**（清单见第六节）。

## 二、现象与预期

- 现象（用户报告）：1.1 版本下打出升级的至亮之焰只抽 2 张牌、加 2 费。
- 预期：未升级 2 能量 / 抽 2；升级后 3 能量 / 抽 3；最大生命损失恒为 1
  （本 mod 相对 0.111.0 原版的唯一回调点：2 → 1）。

## 三、证据链（根因定位）

### 1. 原版三版本 OnPlay 均读 DynamicVars（升级天然生效）

`STS2-Reference/4.STS2-Decompiled/decompiled-111/MegaCrit.Sts2.Core.Models.Cards/BrightestFlame.cs`
（107 / decompiled-full / 2.STS2-111Reference 逐字相同）：

```csharp
protected override async Task OnPlay(PlayerChoiceContext choiceContext, CardPlay cardPlay)
{
    await PlayerCmd.GainEnergy(base.DynamicVars.Energy.IntValue, base.Owner);
    await CardPileCmd.Draw(choiceContext, base.DynamicVars.Cards.BaseValue, base.Owner);
    await CreatureCmd.LoseMaxHp(choiceContext, base.Owner.Creature, base.DynamicVars.MaxHp.BaseValue, isFromCard: true);
}

protected override void OnUpgrade()
{
    base.DynamicVars.Energy.UpgradeValueBy(1m);
    base.DynamicVars.Cards.UpgradeValueBy(1m);
}
```

三版本 `CanonicalVars` 除 MaxHp（107/110=1m，111=2m）外均为
`EnergyVar(2)`、`CardsVar(2)`，即升级后应为 3/3。

### 2. v1.1 mod 把 OnPlay 写死为 2/2（断点）

`TMP/04-历史版本源码/RevertBrightestFlame（1.1版本存档）/Patches/BrightestFlameOnPlayPatch.cs`
（修复前，1.1 安装包同款）：

```csharp
await PlayerCmd.GainEnergy(2m, instance.Owner);          // ← 固定 2
await CardPileCmd.Draw(choiceContext, 2m, instance.Owner); // ← 固定 2
await CreatureCmd.LoseMaxHp(choiceContext, instance.Owner.Creature, 1m, isFromCard: true);
```

### 3. 升级机制只作用于 DynamicVars

`CardModel.UpgradeInternal()`（decompiled-111
`MegaCrit.Sts2.Core.Models/CardModel.cs` L2129–2136）调用 `OnUpgrade()`，
后者通过 `DynamicVar.UpgradeValueBy`（`DynamicVar.cs` L143–147）把
`BaseValue` 2 → 3。卡面描述（`CardModel.GetDescriptionForPile` L1372–1375
`DynamicVars.AddTo(description)`）渲染的是升级后的 3/3，而打出的字面量仍是 2/2
→ 卡面与实测不一致，且升级本身失去收益。这正是用户观察到的症状。

## 七、其余审阅发现（未在本次改动中处理，建议后续处理）

1. **ShapeGuard 检查项与文档承诺不完全一致**
   （`Patches/BrightestFlameShapeGuard.cs` L26–46）：注释称检查"全部补丁目标
   成员"，但漏检 `BrightestFlame.CanonicalVars` getter 与
   `CardEnergyCost.Canonical` getter。当前版本无影响；若未来游戏删改这两个成员，
   `Harmony.PatchAll` 会在中途抛错，存在"部分补丁已应用、其余未应用"的隐患。
   建议补两条 `AccessTools.PropertyGetter(...) != null` 检查。
2. **发布仓库仍是 v1.1 旧码**：`TMP/01-旧Git仓库/STS2Mod-Revert-Brightest-Flame`
   （origin: github.com/Rim-World/STS2Mod-Revert-Brightest-Flame）以及
   `TMP/04-历史版本源码/RevertBrightestFlame（1.0/1.1版本存档）` 目录都还是未修复副本。
   存档目录建议保持只读快照；发布仓库应在发布 1.1.1 前同步本次 OnPlay 修复与
   manifest 版本号（是否提交/推送属发布操作，由你决定）。
3. **升级预览路径**（`CardCmd.Upgrade` / `HoverTipFactory` 等对
   `UpgradeInternal` 的调用）均经过本 mod 的 OnUpgrade 补丁，当前无问题；
   若未来引擎改动 `DynamicVar.UpgradeValueBy` 语义，需回归本 mod 的
   `OnUpgradePatch` 与 `CanonicalVarsPatch`。
