# v0.113.0 失效评估：`CreatureCmd.LoseMaxHp` 签名变更

- 日期：2026-11-13
- 评估对象：本 mod v1.1.1（面向 v0.111 构建）
- 评估方式：静态比对 v0.111 / v0.113 反编译源码与 mod 源码；只读，未构建、未实机
- 结论：**已失效**。在 v0.113 打出「至亮之焰」时，mod 调用的旧方法签名不存在，抛 `MissingMethodException`。

## 证据

| 位置 | 内容 |
|---|---|
| `STS2-Reference/2.STS2-111Reference/decompiled/MegaCrit.Sts2.Core.Commands/CreatureCmd.cs:866` | v0.111：`LoseMaxHp(PlayerChoiceContext, Creature, decimal, bool isFromCard)` |
| `STS2-Reference/3.STS2-113Reference/decompiled/MegaCrit.Sts2.Core.Commands/CreatureCmd.cs:942` | v0.113：`LoseMaxHp(PlayerChoiceContext, Creature, decimal, CardModel? cardSource)` |
| `9.SRC/RevertBrightestFlame/Patches/BrightestFlameOnPlayPatch.cs:34` | 本 mod 以 `isFromCard: true` 调用旧 4 参重载 |
| `STS2-Reference/3.STS2-113Reference/decompiled/MegaCrit.Sts2.Core.Models.Cards/BrightestFlame.cs:31` | 原版同步改为传 `this`，是「至亮之焰」在 111→113 的唯一源码差异 |

`isFromCard:` 是命名实参，只在编译期有意义。编译后的 IL 绑定方法签名 `(PlayerChoiceContext, Creature, decimal, bool)`。v0.113 中该签名不存在，只剩 `(PlayerChoiceContext, Creature, decimal, CardModel?)`。

## 影响

- 触发条件：mod 启用（默认启用），打出「至亮之焰」。
- 表现：`OnPlay` 的 prefix 内抛异常。获得能量、抽牌、失去最大生命三项均不结算。
- 异常是否被游戏捕获、整次出牌是否中断，未实机验证。
- 形状守卫未覆盖：`BrightestFlameShapeGuard.ValidateStatic()` 只检查属性 getter、`OnPlay`、`OnUpgrade`、`ExtraHoverTips`，不查 `CreatureCmd.LoseMaxHp`，因此不会自动停用。

## 修复方向

1. 反射分派：运行时检测 4 参 `CardModel?` 与 4 参 `bool` 两个签名，命中哪个调哪个。本系列其它回调 mod 已有同套路。
2. 若只保留 v0.113 目标，改为传卡牌实例（`instance`）作卡源。
3. 把 `CreatureCmd.LoseMaxHp` 加入形状守卫，缺失时整组补丁不启用，避免半启用。

## 补充（2026-11-13 独立审查）

- 版本事实补齐：107 的 `CanonicalVars` 为 `MaxHpVar(1m)`，111/113 为 `MaxHpVar(2m)`；本 mod 的存在理由就是 111 的 2→1。107 不在加载范围（`min_game_version = 0.111.0`）。
- `isFromCard` 与 `cardSource` 不等价：113 的 6 参 `Damage` 会把 `dealer` 推导为 `cardSource?.Owner.Creature`，并新增 `BufferPower` 对 `cardSource is BrightestFlame` 的特判（不消耗 Buffer）；`Rupture` 在 `cardSource` 非空时延迟到 `AfterCardPlayed` 结算，但两种情况下都会触发。修复时传卡牌实例，与 113 原版一致。
- `Rupture`「传 null 不触发」的旧说法不成立。
- 验收陷阱：0.113 设置里本地 `mods/RevertBrightestFlame` 被禁用，实际加载创意工坊 `3783912778` 的旧 1.1.1；验收前必须确认加载路径指向新构建。
