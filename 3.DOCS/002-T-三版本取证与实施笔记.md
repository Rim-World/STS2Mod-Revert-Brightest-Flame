# 调研与实施笔记：RevertBrightestFlame（回调至亮之焰）

> 工程：`9.SRC/RevertBrightestFlame`；2026-08-15 创建；游戏版本 v0.111.0

## 一、需求与结论

- 将 111 版「至亮之焰」（Brightest Flame）的「每次使用损失 2 最大生命值」回调为损失 1
  （v0.107.1 / v0.110.x 原数值）；仅改数字，其余效果与升级不变。
- 版本门槛：`min_game_version = "0.111.0"`（仅 0.111.0 及以上加载生效）。
- 作者：再玩小卡组找人弄你；mod 版本 1.0；图标：空白占位图。

## 二、三版本取证（解包源码对比）

| 版本 | 素材来源 | `CanonicalVars` 中 MaxHp |
|---|---|---|
| 107 | `sts2-phantom-killer-mod/refs/decompiled-107` | `MaxHpVar(1m)` |
| 110 | `sts2-phantom-killer-mod/refs/decompiled-full` | `MaxHpVar(1m)` |
| 111 | `STS2Mod/refs/decompiled-111` | `MaxHpVar(2m)` ← 111 削弱 |

- `BrightestFlame`（sealed，`MegaCrit.Sts2.Core.Models.Cards`）：Skill / Ancient / Self / 0 费。
- `OnPlay` = `PlayerCmd.GainEnergy(Energy.IntValue)` + `CardPileCmd.Draw(Cards.BaseValue)`
  + `CreatureCmd.LoseMaxHp(MaxHp.BaseValue, isFromCard: true)`。
- `OnUpgrade` = 能量 +1、抽牌 +1；MaxHp 不随升级变化。
- 其他引用：`EventCardPool`（事件卡池）、`Storybook` 遗物（HoverTip/生成）、`AbstractModelSubtypes`（注册）。
- 卡面文本为 DynamicVar 占位符驱动：`CardModel.GetDescriptionForPile` → `DynamicVars.AddTo(description)`
  → LocString 替换 `{MaxHp}` 等占位符（升级时能量/抽牌数字变化即为铁证）。

## 三、实现方案

单个 Harmony 补丁：`BrightestFlame.CanonicalVars` getter Postfix，返回
`[ MaxHpVar(1m), EnergyVar(2), CardsVar(2) ]`。

- 效果：`OnPlay` 读取 `DynamicVars.MaxHp.BaseValue` → 1（`CreatureCmd.LoseMaxHp` 第二个实参）。
- 文字：`{MaxHp}` 占位符 → 显示 1，无需任何本地化文件。
- 缓存：`CardModel.DynamicVars` getter 实例级懒加载（`_dynamicVars ??= new DynamicVarSet(CanonicalVars)`）；
  加载顺序为 ModLoaded（补丁）→ ModelDb.Init（规范实例构造），故无需清缓存。
- 写法先例：`STS2RevertAnthony/Patches/` 下 50+ 个 `CanonicalVars` 补丁（如 Begone）。

## 四、版本检查机制（反编译确认）

- `ModManager.Initialize(fileIo, settings, gameVersion)` 接收 `SemanticVersion`（来源 `release_info.json`，
  本机 = `v0.111.0`）。
- `ModManifest.minGameVersion` 解析为 `SemanticVersion` 后比较：
  `_gameVersion.CompareTo(minGameVersion) >= 0` 才放行；否则
  `mod.state = Failed` + `MOD_ERROR.GAME_VERSION_UNSUPPORTED`（mod 管理界面显示版本不支持，拒绝加载）。
- 语义：`min_game_version` 是最低门槛 → 0.111.0 及以上全部放行，恰好满足「只在高版本启用」，
  且 107/110 上卡牌本来就是损失 1，mod 无意义，被门槛正确拦截。

## 八、v1.1.1 缺陷修复（2026-09-07）

### 现象与根因

- 现象：1.1 重构后，打出升级的至亮之焰只获得 2 能量、抽 2 张（应为 3/3）。
- 根因：`BrightestFlameOnPlayPatch` 在 ADR-002 中把能量/抽牌写成字面量 `2m`，
  而升级只修改 `DynamicVars`（2→3），字面量不随之变化 → 升级收益被吞。
  原版三版本 OnPlay 均读 `DynamicVars.Energy.IntValue` / `DynamicVars.Cards.BaseValue`。

### 修复（对应 ADR-003）

- OnPlay 改为 `PlayerCmd.GainEnergy(instance.DynamicVars.Energy.IntValue, ...)` +
  `CardPileCmd.Draw(choiceContext, instance.DynamicVars.Cards.BaseValue, ...)`；
  最大生命损失保持固定 `1m`。
- 职责切分：基础 2/2/1 由 CanonicalVars 补丁写死；升级 +1/+1 由 OnUpgrade 补丁
  （DynamicVar.UpgradeValueBy）记录；OnPlay 只执行 DynamicVars。
- manifest 升 1.1.1；重跑 build.ps1 部署到游戏 `mods\RevertBrightestFlame`。

### 回归验证（用户实机）

1. 未升级：+2 能量、抽 2、-1 最大生命；
2. 升级后：+3 能量、抽 3、-1 最大生命；
3. 升级预览与实际一致；mod 列表无报错。
